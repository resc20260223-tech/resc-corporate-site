v1.1-01

どこから入って、どこまでやるか

SCOPE

6つのサービスは、入口が2系統に分かれています。いま無いものを新しくつくる「つくる（BUILD）」が3つ、すでに動いているものを整える「ととのえる（TUNE）」が3つ。どちらから入っても、動きはじめたあとは同じ形になります。運用しながら版を重ねていく形です。

サービスは2つの系統に分かれています。つくる（BUILD）は S-01 Webサイト制作、S-02 Webアプリ開発、S-03 システム開発の3つ。ととのえる（TUNE）は S-04 DXコンサルティング、S-05 業務システム改善、S-06 保守・運用サポートの3つ。どちらの系統も、動いている状態に合流し、そこから v1.1、v1.2 と版を重ねていきます。

v1.1-02

つくる — S-01 / S-02 / S-03

BUILD

いま無いものを、新しくつくる3つです。どれも最初の版はいちばん小さくつくります。全部入りをつくってから直すより、要るものだけを先に動かして、使いながら足したほうが早く着くためです。

S-01  つくる / BUILD

Webサイト制作

費用：要相談 / 主に扱う範囲：画面・体験（ST-01）

会社の"顔"となる、伝わるWebサイトを。

誰に何を伝えるサイトなのかを決めるところから始めます。掲載する情報の優先順位を整理し、更新のしやすさまで含めて設計します。

  • −ご相談時によくある状態：何年か前につくったまま更新が止まっていて、いま伝えたいことが載っていない
  • +やること：誰に何を伝えるサイトなのかを決め、載せる情報の順番から組み直します
  • +やること：公開したあとにご自身で更新できる形にして、更新の手順もあわせてお渡しします

ここでやらないこと：広告の運用代行と、記事の継続執筆はお引き受けしていません。更新できる仕組みと、書き方の型をお渡しするところまでです。

S-02  つくる / BUILD

Webアプリ開発

費用：要相談 / 主に扱う範囲：画面・体験（ST-01）／業務ロジック（ST-02）／データ（ST-03）

業務にフィットする、使われ続けるアプリを。

毎日使うものだからこそ、画面の数や入力の手間を削ります。裏側のデータの持ち方まで含めて、業務の流れに合わせて組み立てます。

  • −ご相談時によくある状態：表計算のファイルが人ごとに分かれていて、同じ内容を二度書いている
  • +やること：毎日使う画面から先につくります。入力の手間と画面の数を減らす場所を、最初に決めます
  • +やること：2週間をひと区切りにして、区切りごとに動くものをお見せしながら進めます

ここでやらないこと：既製のパッケージ製品の販売・再販はしていません。既製品で足りる場合は、その旨をお伝えします。

S-03  つくる / BUILD

システム開発

費用：要相談 / 主に扱う範囲：業務ロジック（ST-02）／データ（ST-03）／運用・基盤（ST-04）

自社の業務に合わせた、オーダーメイドの仕組みを。

既製品に業務を合わせるのではなく、いまの業務に合う形をつくります。ルールとデータ、そして動かし続ける土台まで一続きで考えます。

  • −ご相談時によくある状態：業務のルールが人に付いていて、担当が変わると回らなくなる
  • +やること：いまの業務に合う形で、ルールとデータの持ち方から組み立てます
  • +やること：すでに動いている販売管理や会計の仕組みとは、データ連携でつなぎます

ここでやらないこと：機器やネットワークの販売・設置は行っていません。回線や機器が絡む場合は、範囲を分けたうえでご相談します。

v1.1-03

ととのえる — S-04 / S-05 / S-06

TUNE

すでに動いているもの、あるいはまだ形になっていない相談を整える3つです。つくらないという結論も、ここでは答えのひとつとして扱います。

S-04  ととのえる / TUNE

DXコンサルティング

費用：要相談 / 主に扱う範囲：4区分すべて（ST-01〜ST-04）

何から始めるか、から一緒に整理します。

つくる前に、どこが詰まっているのかを見ます。画面の話に見えて原因がデータ側にあることも多いので、業務の4区分を一度ぜんぶ並べて考えます。

  • −ご相談時によくある状態：「DXを進めたい」とは決まっているが、何から手をつけるかが決まっていない
  • +やること：困っていることをそのまま聞いて、画面・業務ロジック・データ・運用基盤の4区分に並べ替えます
  • +やること：いちばん効くところから小さく試す順番を、ご一緒に決めます

ここでやらないこと：補助金の申請代行と、人事制度そのものの設計はお引き受けしていません。整理した結果、つくらないという結論になることもあります。

S-05  ととのえる / TUNE

業務システム改善

費用：要相談 / 主に扱う範囲：画面・体験（ST-01）／業務ロジック（ST-02）／データ（ST-03）

使いにくさの原因を見つけ、丁寧に直す。

使いにくさは、たいてい画面だけの問題ではありません。入力の手順やデータの持ち方までさかのぼって、直す場所を決めてから手を入れます。

  • −ご相談時によくある状態：使いにくいと言われているが、どこを直せばいいのかが分からない
  • +やること：使っている画面と手順をそのまま見せてもらい、詰まっている場所を先に特定します
  • +やること：直す場所と順番を決めてから手を入れます。つくり直す前に、直すという選択肢もお出しします

ここでやらないこと：他の会社が開発したシステムは、ソースコードと動かしている環境を確認できる場合にご相談を承ります。確認できないときは、つくり直しのご提案になります。

S-06  ととのえる / TUNE

保守・運用サポート

費用：要相談 / 主に扱う範囲：データ（ST-03）／運用・基盤（ST-04）

リリース後も、安心して任せられる体制を。

動き続けている状態を保つ仕事です。データの増え方や動かしている環境を見ながら、直す・足す・整えるを続けます。

  • −ご相談時によくある状態：リリース済みのシステムに手が入らず、現場からの要望が溜まっている
  • +やること：監視と障害の一次対応、それに軽微な修正までを月額の定額で承ります
  • +やること：月次で直すもの・足すものを決めて、次の版に入れます

ここでやらないこと：24時間365日の常時対応は行っていません。受付は営業時間内（9:30〜18:30／土日祝休み）です。

v1.1-04

お見積りの出し方

ESTIMATE

費用はすべて要相談です。規模と内容によって変わるため、個別にお見積りします。金額そのものはここに書けませんが、どうやって出しているかは書けるので、そちらを置いておきます。

出し方
要件を機能の単位に分解し、それぞれの想定工数を積み上げて出します分解したものはそのままお渡しするので、どこにいくらかかっているかが見えます
タイミング
「02 設計」の段階で出します相談だけの段階では概算もお出ししていません。外れてしまうためです
内訳の区分
設計／実装／テスト／リリース作業／運用開始後の初期サポート
保守契約
月額の定額（監視・障害の一次対応・軽微な修正）＋ 追加の開発は都度お見積りという形が基本です。内容に合わせて相談して決めます
契約の形
準委任・請負のいずれも案件の性質に合わせて、相談して決めます
できることより、やらないことを先に書く。

範囲がはっきりしていないお見積りは、あとで食い違いのもとになります。だから設計の段階で、つくるものとつくらないものを分けた表をお渡しして、そこから金額を出しています。

  • −よくある状態：一式いくら、の見積りだけがあって、中身が読めない
  • +やっていること：機能の単位に分解した表と、その積み上げをそのままお渡ししています

目安のレンジや人月の単価は出していません。案件ごとに前提が違いすぎて、幅の数字がひとり歩きしてしまうためです。
